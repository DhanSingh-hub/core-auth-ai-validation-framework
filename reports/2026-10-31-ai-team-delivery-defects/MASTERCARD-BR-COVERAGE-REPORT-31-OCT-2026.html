Executive summary

Just over a third of grounding Test BRs are confirmed; most still need review

The 31 October AI run built two Mastercard packages: Mastercard Credit (36 scenarios, 450 test cases) and Mastercard Fleet (24 scenarios, 299 test cases). Each package carries its own Test BR catalog — the ATL105 spec rules the AI grounded its scenarios in (scenario_supporting_rules.csv). Of the combined 1,404 Test BRs across both packages, 513 (36.54%) carry no "requires review" flag and are treated here as confirmed-covered; the remaining 891 (63.46%) require SME or QA review before they can be counted as covered.

What this number is, and is not

This is package-scoped candidate coverage: the denominator is each package's own AI-built supporting-rule catalog, not the separate 1,343-row independent Test Solution BR catalog (which uses a different ID scheme and is not joined here). It also is not semantic approval, SME sign-off, or execution/pass status — both packages are explicitly marked mapping_status = candidate in their build metadata.

Methodology and limitations

Read this as package-scoped rule-grounding confidence, not semantic coverage

  • Denominator ("Test BR"): the distinct rule_id rows in each package's own requirements_scenarios/scenario_supporting_rules.csv — the ATL105 spec rules the AI's scenario generator cited as grounding for that package's scenarios. Mastercard Credit = 590 (576 request + 14 response-check); Mastercard Fleet = 814 (793 request + 21 response-check).
  • Numerator ("covered"): rules in that same file with no requires_review flag set. All rules in the file already have scenario_count ≥ 1 by construction (unreferenced rules are not listed), so this is a confidence/review measure layered on top of baseline linkage, not a reach/non-reach measure.
  • Why this is not joined to the independent 1,343-row Test Solution BR catalog: that catalog uses segment-anchored IDs (for example BR-RULE-SEG104-R-002), while this delivery's rule catalog uses page-anchored IDs (for example BR-104-2). The two ID schemes do not share a key, and no crosswalk file linking them was found in the 31 October output or in prior review folders. Building one would require the same token/segment-matching engine used in the 2026-10-14 AI-to-Test-BR crosswalk report, which was intentionally out of scope for this page.
  • Build state: both packages carry mapping_status = "candidate" and state = "CANDIDATE" in their build metadata. No SME or Test Solution owner has adjudicated MATCH/PARTIAL/NOT_MATCH against this rule set.
  • Scope exclusions: 90 (Credit) and 120 (Fleet) scenario combinations were deliberately excluded as not applicable to Mastercard and are outside every count on this page.
  • This page does not assert test execution, pass/fail status, or production behavior. It also does not supersede or close any of the 8 open issues in the 31-Oct defect report.
