Executive summary

About a quarter of the independent catalog has an automated candidate match; most does not

This is a different question from the 37.60% figure in the prior report. That number was package-scoped: denominator = the AI's own 2,755-rule catalog, numerator = rules the AI itself didn't flag requires_review. Here the denominator is instead the full 1,343-row independent Test Solution BR catalog — a fixed, externally-authored baseline that does not change with each AI delivery — and the numerator is whatever this automated engine can show the 5-10 delivery's own rule text plausibly addresses. Of 1,343 independent Test BRs, 370 (27.55%) have at least one candidate match at or above the matching floor; 81 (6.03%) reach the stronger “semantic candidate” tier; 973 (72.45%) have no candidate at all.

This is a brand-new, automated crosswalk — read it as a triage aid, not a coverage certificate

No file anywhere in this repository previously joined the 1,343-row independent catalog (segment-anchored IDs, e.g. BR-RULE-SEG104-R-002) to any AI delivery's rule catalog (page-anchored IDs, e.g. BR-104-2) — confirmed absent in both prior BR-coverage HTML reports and the 2026-10-31 consolidated Mastercard/Maestro report. This page builds that join for the first time, reusing the token-overlap scoring approach already present in this workspace's coverage_engine.py (previously spot-checked by a human reviewer on ATL105 Segment 103: automated 66.7% vs manual 62.5%, a different population from this one).

What a “candidate” means: the engine found overlapping, IDF-weighted vocabulary (and, for the strongest tier, a literally shared ATL105 section number) between a Test BR's own text and at least one AI rule's statement. It is not SME confirmation, not semantic equivalence, and not evidence the AI delivery actually implements or tests that requirement. See “Known limitations” below for two concrete worked examples, including a false positive.

Methodology

How the match score is computed

  • Denominator: all 1,343 rows of All_TestSolution_BRs.xlsx, sheet “All Test Solution BRs” — the independent, AI-authorship-free Test Solution catalog. Every row counted, none excluded (including the 381 formulaic BR-APPF rows and the 16 rows tagged to non-in-scope network types).
  • Candidate pool: all 2,755 rows across the 5 networks' requirements_scenarios/scenario_supporting_rules.csv files in the 5-10 delivery (the same source used for the prior 37.60% report).
  • Tokenization: lowercase, strip punctuation (keep digits/periods for section numbers), drop a stopword list reused verbatim from this workspace's coverage_engine.py (includes generic ATL105 vocabulary like “segment”, “element”, “field”, “value”, “data” so these alone cannot drive a match).
  • IDF weighting (added for this pass): each token is weighted by log((N+1)/(df+1)) + 1 across the 2,755-rule AI corpus, so rare/specific words (“ucaf”, “dsrp”, “cryptogram”) count far more than common ones (“transaction”, “type”, “receipt”). Without this, short Test BR statements whose only surviving words were generic terms spuriously matched unrelated AI rules on those common words alone — confirmed and fixed during calibration of this run (see diagnostic evidence retained alongside the source scripts).
  • Score: 0.5 × weighted_overlap_coefficient + 0.5 × weighted_recall, plus a flat +0.15 if the Test BR's own Segment/Section number is literally cited (as a dotted-decimal ATL105 section number, e.g. “10.1.7”, or a bare segment number) inside the AI rule's statement text.
  • Tiers: Strong candidate needs score ≥ 0.70 and the anchor citation; Semantic candidate needs score ≥ 0.55; Weak candidate needs score ≥ 0.35 (the matching floor — pairs scoring below this are treated as no match at all, not merely a low score). Tier names deliberately avoid the word “confirmed”, consistent with every other report in this series.
  • Per-Test-BR result = its single best-scoring AI rule across all 5 networks combined (shown in the appendix); per-network reach is computed separately as a yes/no (does this network alone clear the floor for this Test BR).
  • Prior calibration: this scoring/tiering shape (though not the IDF weighting or the anchor-citation signal, both new to this pass) was previously spot-checked by a human reviewer against ATL105 Segment 103 in coverage_engine.py/segment_report.json: automated 66.7% vs manual 62.5%, within ~4 points — a different AI source and a different (601-row, segment-rule-catalog-only) denominator than used here, so treat it as directional reassurance about the general approach, not a validated accuracy figure for this specific 1,343-row run.
