## 1. Introduction

Market Basket Data follows InComm ISO 8583 Generic Interface v6.2.3 Appendix B. The transaction type is the 3-digit code sent in Merchant Supplementary Data: 310 Benefit Eligibility & Balance Lookup, 910 Item Qualification, 920 Limited Spend, 200 Limited Spend Refund.

- **INCOMM-MBD-2023-1-L002** (p.4): Market Basket Data is formatted per rules adapted from the InComm ISO 8583 Generic Interface Specification, Version 6.2.3, Appendix B.
- **INCOMM-MBD-2023-1-L003** (p.4): The transaction type is the 3-digit value sent in Merchant Supplementary Data: 310 Benefit Eligibility & Balance Lookup, 910 Item Qualification, 920 Limited Spend, 200 Limited Spend Refund.

## 1.1 Dataset Format

Every dataset is a modified TLV: 2-char Tag + 3-digit Length + 8-char bitmap + field values. Length counts bitmap and values but not Tag/Length. Worked example: DV0134000000001.01.

- **INCOMM-MBD-2023-1-L004** (p.4): Each dataset is a modified TLV: a 2-character Tag, a 3-digit numeric Length, an 8-byte bitmap, then the dataset field values.
- **INCOMM-MBD-2023-1-L005** (p.4): The Length counts the bitmap(s) and all primary and continuation elements, but not the Tag or the Length itself.
- **INCOMM-MBD-2023-1-L006** (p.4): Dataset bitmaps are 32-bit bitmaps represented by eight ASCII bytes (eight hexadecimal characters).
- **INCOMM-MBD-2023-1-L007** (p.4): A DV dataset carrying only Bit 2 with value 01.01 is rendered as DV0134000000001.01 (Tag DV, Length 013, bitmap 40000000, value 01.01).
- ❓ **INCOMM-MBD-2023-1-Q13** (QE_INTERPRETATION_PENDING_SME): Section 1.1's hex example (44 56 30 30 39 34 ... 31 2E 30 31) decodes to DV 009 40000000 1.01, which conflicts with the ASCII example DV0134000000001.01. _QE decision: User decision 2026-10-30: the ASCII example is authoritative (8-byte bitmap + 5-byte value = Length 013); the hex line is treated as a documentation typo._
- ❓ **INCOMM-MBD-2023-1-Q15** (QE_INTERPRETATION_PENDING_SME): The document does not state how fixed-width fields shorter than their maximum are padded. _QE decision: User decision 2026-10-30: fields are fixed width and concatenated in bit order; n is right-justified zero-filled; a, an and ans are left-justified space-filled._
- ❓ **INCOMM-MBD-2023-1-Q16** (QE_INTERPRETATION_PENDING_SME): The bit-to-character mapping of the 8-byte ASCII bitmap is not stated. _QE decision: User decision 2026-10-30: the bitmap is 8 hexadecimal characters with Bit 1 as the most significant bit, so 40000000 means only Bit 2 is present (consistent with the ASCII example)._

## 1.3 DV Dataset

DV is mandatory for every new IH implementation. Bit 2 Dataset Version (MM.mm, supplied by InComm) is required; Offer/Purse File Versions are required only for non-real-time implementations.

- **INCOMM-MBD-2023-1-L010** (p.5): The DV dataset is required for all new IH implementations; Bit 2 Dataset Version (MM.mm) is required and its value is supplied by an InComm integration project resource.
- **INCOMM-MBD-2023-1-L011** (p.5, 6): Offer File Version (Bit 3) and Purse File Version (Bit 4) are required only when the implementation does not exchange a market basket in real time, and are not applicable otherwise.

## 1.4 PI Dataset

One PI per distinct product line: item code, quantity, net price, POS and InComm (MBAS) discounts, eligibility flags, redemption amount, item reference number and purse link. Amounts are in cents; split responses keep the original Item Reference Number.

- **INCOMM-MBD-2023-1-L012** (p.6): A PI dataset is required when IH must evaluate the market basket to authorize a discount, payment or refund.
- **INCOMM-MBD-2023-1-L013** (p.6): Item Code (n 14) is the UPC/EAN13 without check digit, right-justified and zero-filled; suppressed codes must be expanded.
- **INCOMM-MBD-2023-1-L014** (p.6): Quantities are combined into a single PI when Bits 2, 5, 10, 11, 17 and 18 are identical.
- **INCOMM-MBD-2023-1-L015** (p.6): Price is the single retail price shared by all items in the PI, net of store and manufacturer discounts/coupons; tax is excluded on a 910 request.
- **INCOMM-MBD-2023-1-L016** (p.7, 9): The InComm (MBAS) discount total is quantity times per-item amount: manufacturer = Bit 6 x Bit 7, store = Bit 15 x Bit 16.
- **INCOMM-MBD-2023-1-L017** (p.7): Redemption Request Amount is extended price (quantity x net unit price) plus applicable tax, in cents, and is required for 920 and 200.
- **INCOMM-MBD-2023-1-L018** (p.7, 9): POS-applied manufacturer/store discount amounts (Bits 10, 17) are already netted out of Price; their Type (Bits 11, 18: P, E, M, X) is required when the amount is present or when no further discounts are allowed.
- **INCOMM-MBD-2023-1-L019** (p.8): Adjustment to Price is the amount InComm paid or discounted for the whole PI, including the quantity multiplier (e.g. 2 x $0.75 = $1.50), in cents.
- **INCOMM-MBD-2023-1-L020** (p.8): Item Reference Number must be unique per PI across the whole request (not necessarily contiguous); responses may be unordered and a multi-quantity PI may be split, each part keeping the original Item Reference Number.
- **INCOMM-MBD-2023-1-L021** (p.9): Purse ID links a PI to a PU; 000 means no purse association, and Item Qualification responses always carry 000.
- **INCOMM-MBD-2023-1-L033** (p.8): A multi-quantity PI may be split in the response when a discount applies to only part of the quantity (Item Qualification), when a purse balance is depleted giving a full payment PI, a partial payment PI and a not paid PI (Limited Spend), or when several purses fund the items (Limited Spend).
- **INCOMM-MBD-2023-1-L034** (p.7): Tax in the Redemption Request Amount follows the retailer's POS business rules, and states differ on whether discounts are taxed.

## 1.6 PU Dataset

InComm returns one PU per active purse, including zero-balance purses: description, purse ID, remaining balance, amount authorized, response code; unique ID and redemption amount only for non-real-time.

- **INCOMM-MBD-2023-1-L023** (p.11): PU datasets appear only in IH responses, one per active purse on the account, including purses with a zero balance.
- **INCOMM-MBD-2023-1-L024** (p.11): Purse Description should be shown to the consumer with the balance at the end of the transaction.
- **INCOMM-MBD-2023-1-L025** (p.12): Amount Authorized is never negative, is zero for declined or uninvolved purses, and is required for 920 and 200.
- **INCOMM-MBD-2023-1-L026** (p.12): Purse Unique ID (Bit 8) and Redemption Request Amount (Bit 9) apply only to implementations that do not exchange a market basket in real time.

**Enforcement gaps**

- INCOMM-MBD-BR-001: The validator receives the code as a parameter; reading it from Segment 111 is not demonstrated.
- INCOMM-MBD-BR-008: Reported for review, not rejected, until Q01 is answered.
- INCOMM-MBD-BR-012: Segment-level length is outside Market Basket Data; only the 2300 field maximum is checked (BR-010).
- INCOMM-MBD-BR-013: Whether IH evaluation is needed is a business context, not visible in the data.
- INCOMM-MBD-BR-014: Check-digit removal and UPC-E expansion cannot be verified without the original barcode.
- INCOMM-MBD-BR-016: Net-of-discount and tax-exclusion are business calculations; Price units await Q06.
- INCOMM-MBD-BR-018: Applying the discount at the POS is device behavior.
- INCOMM-MBD-BR-019: Position 3 and reserved filler await Q02.
- INCOMM-MBD-BR-021: Price is not sent on 920/200 and tax follows retailer business rules that vary by state (some states tax discounts, some do not), so the arithmetic cannot be checked.
- INCOMM-MBD-BR-022: A missing Adjustment to Price is reported for review, not rejected, until Q18 is answered.
- INCOMM-MBD-BR-026: A missing Purse ID in a response without any PU is reported for review, not rejected, until Q19 is answered.
- INCOMM-MBD-BR-028: Which purses are active is account state held by InComm.
- INCOMM-MBD-BR-029: Device display/receipt checkpoint, not message data.
- INCOMM-MBD-BR-030: Zero for declined purses needs the purse Response Code meaning (Q08).
- INCOMM-MBD-BR-031: Only the an 2 format is checked until values are supplied (Q08).
- INCOMM-MBD-BR-032: Disagreeing duplicated columns are reported, not enforced.
- INCOMM-MBD-BR-033: OF is outside the ATL105 composition until Q01 is answered.
- INCOMM-MBD-BR-034: Type-to-transaction mapping awaits Q05; totalAmountAwarded conversion is a retailer calculation.
- INCOMM-MBD-BR-036: The actual Dataset Version value is not known (Q07), so only the MM.mm pattern is checked.

## Draft validator

`python scripts/ingest-incomm-market-basket.py --validate <MarketBasketData> --direction request|response --txn 310|910|920|200 [--request <requestData>]`
returns `PASS`, `REVIEW_REQUIRED` or `FAIL`; each finding carries the validator rule ID that its BR declares. It is a draft checker for Segment 151/152 data, not an execution oracle.
