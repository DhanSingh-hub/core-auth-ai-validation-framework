# Segment 120 - Print Data 2 Segment

**Specification:** BUYPASS ATL105 2026-3, Section 12.18
**Segment:** 120
**Purpose:** Print Data 2 Segment — carries large blocks of print/receipt
data on a Financial Transaction Response or EMV Financial Transaction
Response. This is a response-side companion segment; it never appears on a
request.

## Scope

This module covers:

- The Segment 120 envelope: Segment Type, Segment Length, and Print Data
- The Segment Length field, always exactly 4 digits for Segment 120
  (confirmed via Element 84 spec text, `P-02-WIDTH` resolved)
- The 999-character Print Data cap and the 1,009-character total-segment cap
  as two independently enforced limits (a residual 1-character arithmetic
  gap between them remains open, `P-02-RESIDUAL`)
- Field-separator placement (2 separators, no trailing separator — unlike
  Segment 111)
- Response-only applicability (Financial Transaction Response / EMV
  Financial Transaction Response, never a request)
- Segment 120's position relative to other response-side companions
  (resolved: literal spec text takes priority over an AI-template ordering
  artifact, `P-01`)
- Business-requirement, scenario, test-case, and test-data analysis for all
  of the above, cross-checked directly against the AI Solution pipeline
  (`src_Harit_Latest_AI_Sol/src/pipeline`)

It does not claim to validate receipt-formatting business logic beyond the
Blackhawk `\` line-delimiter convention (`SEG120-R-008`, `P-03`, still open).
"Last segment" ordering (`SEG120-R-007`) is now hard-enforced following the
`P-01` resolution described in the
[coverage closure](coverage/README.md).

## Headline Finding (Resolved 2026-09-23)

The AI Solution pipeline's own artifacts initially appeared to disagree on Segment 120's
position: the extracted requirement `BR-263-2` and its generated test cases assert Segment 120 is
always last, while the AI Solution's own generated message templates
(`docs/atl105_complete_templates.json`) place it 3rd of 9-10 segments. Re-examination showed the
template orders segments in strict ascending segment-number order in both cases — a numeric-sort
extraction artifact, not genuine wire-order evidence. `BR-263-2` is therefore treated as
authoritative and is now hard-enforced. See the
[coverage SME note](coverage/segment-120-coverage-sme-tba-note.md) for the full analysis and the
condition under which this resolution should be revisited.
